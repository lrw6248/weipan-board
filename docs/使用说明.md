> 面向完全不懂技术的用户。所有数据源和提醒通道都是**免费的**，不需要付费、不需要买数据、不需要注册任何行情账号。

## 这套信号是什么

看板从上到下是三张卡：

1. **今日信号**：左边三段圆环 + 结论卡（结论 / 还差什么 / 所处阶段），右边三条条件一一对应。每条条件有名称、阈值、进度条、差距，以及它自己的「当前状态」小卡（状态 + 持续多少个交易日）。三条条件的名字是专有名词（微盘 PB / 做多信号 / 扩散指数），名字后面那句小灰字是**对它本身的解释**——说明这个指标在量什么：`绝对估值 · 市净率`、`相对估值 · 分档评分`、`市场情绪 · 均线占比`。**阈值不写在这里**：看条件是「PB > 2.0 已连续 N 个交易日」这行，看差多少是脚下「高出阈值 0.011」这行。标题行、当前值、当前状态三者各说一件事，不重复。做多信号那条的「当前状态」小卡是两行：
   - **标题行右侧**：五颗星（半星按比例填充）就是当前星级，**点它**展开「星级构成」面板。这里只有一个刻度：星，不再写成「2 星」两个字。
   - **第一行**：`当前状态` + `< 3 星` 或 `≥ 3 星`（现在在 3 星线的哪一侧）+ `已连续 N 个交易日`。点这一行同样可以展开「星级构成」。
   - **第二行**：`当前档位的历史表现` 这个标题下面是一张 3 列小表，列头 `20 日 / 60 日 / 120 日`（持有期，不是「最近 N 日」），两行分别是 `胜率` 和 `涨幅`。**点这一块**展开全表。
   - 两个面板**一次只开一个**：打开构成就收起历史，反过来也一样，免得把页面撑得太长。
   - 三个条件的「当前状态」都只写「判定关系 + 已连续 N 个交易日」，不重复右侧已经显示的具体数值：`PB > 2.0`、`< 3 星`、`扩散指数 > 20%`。
   - **星级构成面板**（点右上角星星展开）：
     1. 最上面一条 0–5 星进度条，3 星处画了达标刻度，右边写着距 3 星还差多少（星级本身画在卡片标题行，这里不重复）；
     2. 再下面三格：历史上处于这一档的交易日天数、持有 120 日后胜率、平均涨幅；
     3. **星级构成**分三列并排（`Ⅰ 时序 · 自身历史` / `Ⅱ 截面 · 同源分层` / `Ⅲ 截面 · 公开宽基`），每列一张小表（参照点 / PB / 得星）+ 本组小计，三组小计之和就是右上角那个合计；
   - **档位历史面板**（点第二行小表展开）：
     1. 一张表按星级由低到高排（`0–2 星`、`2.5 星`、`3 星`、`3 星 + PB<2`、`3.5 星`、`4 星`、`4.5 星`、`5 星`），列出持有 20 / 60 / 120 个交易日的**胜率**和**平均涨幅**（各占一列），当前档位整行蓝色高亮；
     2. 最下面三个折叠条：「触发档位统计」「逐次触发明细」「独立复核」。
   - 「3 星 + PB<2」是从 3 星里再筛出 PB<2 的那部分交易日（57 天），**和 3 星那行有重叠**，不是额外一档，所以缩进 + 标「子集」，不参与合计。
   - 两个面板的配色都跟随条件 2（做多信号）的蓝。
2. **全景图**：六个面板共用一根时间轴——PB、做多信号、扩散指数、成交额、市值、深跌深度。每个面板标题右边直接写「当前」读数，不用移鼠标；移上去还能看任意一天的全部数值。时间范围可切「全部 / 3 年 / 1 年 / 6 月 / 3 月 / 1 月」，**默认打开是近 6 个月**（想看更长的历史再点）。每个面板有自己的圆角细框，六段曲线不会混在一起。
3. **信号提醒 / 数据与更新**。

「星级构成」里的三个参照系是**并列**的三列，结构完全一样（参照点 / PB / 得星 / 本组小计）：

| 组 | 名称 | 跟谁比 | 项数 × 分值 |
|---|---|---|---|
| Ⅰ | 时序 · 自身历史 | 微盘 PB 跟自己近 1800 个交易日（约 7 年）的 25% 分位比 | 1 项 × 1 星 |
| Ⅱ | 截面 · 同源分层 | 同一交易日、同一套清洗规则下，把**全A按总市值从大到小**切成四段（第 1–300、301–800、801–1800、1801–3800 名），段内等权调和 PB。四段只覆盖最大的 3800 只；微盘 400 只是同一股票池里最小的 400 只（现在股票池 5001 只，即第 4602–5001 名），**不在这四段里**，所以是「微盘 vs 更大的同门」而不是「微盘 vs 自己那 400 只」 | 4 项 × 0.5 星 |
| Ⅲ | 截面 · 公开宽基 | 沪深300 / 中证500 / 中证1000 / 中证2000 的**官方成分股**，用同一等权调和口径重算 PB（不是指数公司发布的加权 PB，所以跟行情软件的数字不一样） | 4 项 × 0.5 星 |

「时序 / 截面」是统计上的说法：时序＝跟自己的过去比，截面＝跟同一天的别人比。Ⅱ 和 Ⅲ 都属于截面，区别是 Ⅱ 同源（同一个股票池、同一套口径，只差市值大小），Ⅲ 是外部指数。

深跌并进全景图的最下面一个面板：**颜色越深＝跌得越狠**（−16% 中紫 `#A98BF7` → −45% 深紫 `#4C1D95`，最深一档留了亮度，不会黑成一片），柱子长度就是回撤幅度；柱子上那条**深紫细线**是逐日回撤曲线，带一层白色描边，压在最深的柱子上也看得清（这一版把曲线改到柱子**上层**画，之前被柱子盖住了，所以深处只剩一片紫）；深跌区间在其他五个面板上铺一层淡紫底纹。点开「全部深跌低点明细」能看每一次的 PB、信号和之后 20/60/120 天的表现。**深跌用紫罗兰色阶**——红在 A 股是涨，绿色已经是扩散指数的颜色，紫色是这张图上唯一没人用的色相；成交额顺便改成了中性灰蓝，把紫色让出来。


| 条件 | 成立条件 | 现在 | 怎么看 |
|---|---|---|---|
| ① 微盘 PB（绝对估值） | PB < 2.0 | 2.011 | 达标区在左边，点要落进去 |
| ② 做多信号（相对估值） | ≥ 3.0 星（满分 5） | 2.0 | 达标区在右边 |
| ③ 扩散指数（情绪冰点） | 站上 20 日均线占比 < 20% | 41.3% | 达标区在左边 |

- 三条条件一律用**专有名词**做名字（微盘 PB / 做多信号 / 扩散指数），旁边的小灰字说明它属于哪一类（绝对估值 / 相对估值 / 市场情绪），两者是同一件事的两个侧面。
- 差距里的「**个百分点**」是差值，不是涨幅：扩散指数 41.3%、门槛 20%，差 21.3 个百分点。不能写成「高 21.3%」，那是相对变化，含义完全不同。
- 圆环有三段，对应三条条件：成立就点亮（橙 / 蓝 / 绿），没成立就是灰色。
- 三段全亮，圆环下方那张结论卡就变成「分批建仓」，这就是原作者定义的「抄底时刻」。
- 鼠标移到某条条件上，圆环对应那段会加粗；反过来也一样——这样能一眼看出结论是从哪三项推出来的。
- 页面上凡是**带边框的小胶囊按钮**（如「三个条件的计算口径」「全部深跌低点明细」），点一下就地展开、再点一下收起；带 `▾ / ▸` 三角的就是可展开的。条件 2 有两处可展开：标题行右侧那五颗星（展开星级构成）、`当前档位的历史表现` 那张小表（展开全表），都展开在条件 2 **正下方**，不会跑到别的条件下面去。

三条条件的具体算法（来自《微盘抄底，胜率极高》）：

1. **微盘 PB** —— 市值最小 400 只股票（剔除北交所、ST、退市）的市净率等权调和平均
2. **微盘做多信号** —— 满分 5 星，半星一档。时序：低于自身近 1800 日 25% 分位得 1 星；截面：与「同源市值四段」和「四只公开宽基成分」共 8 个对象逐个比较，每低于一个得 0.5 星。**全页只用「星」这一个刻度，不再有「分」**
3. **微盘扩散指数** —— 400 只成分股中站上 20 日均线的比例

**另外还统计了两个结构指标，只作参考、不参与判断：**

- **微盘市值中位数**：400 只里第 200 名的总市值，比平均值更不容易被个别大票带偏
- **微盘成交额**：400 只当日成交金额合计。成交额持续萎缩，通常意味着情绪冰点正在形成。**已回填 2021-12-01 至今日 1199 个交易日**（见下文的近似口径说明），之后每天自动追加。

## 方案 A：双击就能看

1. 双击 `index.html`（用 Chrome / Edge 打开）。
2. 看板只有三张卡：**今日信号**（圆环 + 三条条件 + 当前状态 + 可展开的星级构成）、**全景图**（六面板一张图 + 当前值常显 + 紫色深跌深度）、**信号提醒 / 数据与更新**。

   - **手动录入**当天的 4 个数字 → 保存并应用

## 手机 / 微信里怎么看

`index.html` 是**自包含**的一个文件：样式、脚本、当日数据、全部历史序列都内联在里面（约 520 KB）。
把它单独发到微信「文件传输助手」，手机点开就是完整看板——卡片、圆环、星星、六面板曲线都在。

**不需要额外文件，也不需要任何服务器。**

它为什么能这样：`assets/` 和 `data/` 里是源码与原始数据，`scripts/build_page.py` 会把它们
内联成一份 `index.html`。`run.sh` 和 GitHub Actions 每次更新数据后都会自动跑这一步，
所以你手上这份永远是最新的。

两点说明：

1. **「刷新数据」按钮**：页面里的数据是打包那一刻的。点该按钮会重新加载页面（不联网）；
   要真正更新数据，跑一次 `一键更新.bat` / `run.sh`，再重新发一次文件。
2. **页头不显示「检查信号」按钮**，这是正常的——数据已内联，没有需要联网检查的东西。

> 如果你只想在手机上看，又不想每次重发文件：走下面方案 C，手机存个书签，每天自动最新。

## 方案 B：每天自动算好（推荐）

### 第一次（只做一次）

1. 到 <https://www.python.org/downloads/> 下载 Python 3.9 以上版本并安装。
   **Windows 安装时务必勾选 `Add Python to PATH`**（重要）。
2. 双击 `一键更新.bat`（Mac / Linux 在终端里运行 `bash run.sh`）。
   首次会自动安装两个免费依赖（`requests`、`akshare`），约 1 分钟。

### 以后每天

**交易日收盘后（建议 15:30 之后）双击一次 `一键更新.bat`**，约 20 秒完成。脚本会：

- 拉取全市场 5000+ 只股票的市净率与市值 → 算微盘 PB、平均市值、8 个对比指数 → 算做多信号
- 并发拉取 400 只成分股的日 K（含 MA20）→ 算扩散指数
- 写入 `data/data.js`、`data/data.json`，并追加到 `data/history.csv`

**看板页面开着就会自动刷新，信号有变化会自动提醒**，不用手动刷新浏览器。

### 想连双击都省掉（可选）

Windows「任务计划程序」→ 创建基本任务 → 每天 15:35 → 启动程序，选 `一键更新.bat`。Mac/Linux 用 `crontab`：`35 15 * * 1-5 cd /路径 && python3 update_data.py`。

### 想让提醒发到飞书 / 微信 / 邮箱（可选，免费）

三个渠道互不影响，**填了哪个就走哪个**，也可以同时开。

#### 飞书（推荐：卡片消息，一眼看出成立几项）

1. 手机上打开飞书，进任意一个群（不想打扰别人就**新建一个只有自己的群**）。
2. 点群右上角的 **⋯**（或齿轮）→ **设置** → **群机器人** → **添加机器人**。
3. 选 **自定义机器人**，名字随便起（比如「微盘信号」），点 **添加**。
4. 复制它给出的 **webhook 地址**，形如：

   ```
   https://open.feishu.cn/open-apis/bot/v2/hook/8f3c2a1e-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   ```

5. （可选但建议）在同一页的 **安全设置** 里勾 **签名校验**，把生成的**密钥**也复制下来。
   勾了就必须一并填写，否则飞书会拒收。
6. 填进 `config.json`：

```json
{
  "serverchan_sendkey": "",
  "feishu_webhook": "https://open.feishu.cn/open-apis/bot/v2/hook/这里换成你的地址",
  "feishu_secret": "",
  "email": {}
}
```

#### 微信（Server酱）

1. 把 `config.example.json` **复制一份，改名为 `config.json`**。
2. 打开 <https://sct.ftqq.com>，用微信扫码登录，复制 **SendKey**。
3. 填进 `config.json` 的 `serverchan_sendkey`。

#### 邮件（QQ 邮箱需用授权码，不是登录密码）

```json
{
  "serverchan_sendkey": "",
  "email": {
    "smtp": "smtp.qq.com",
    "port": 465,
    "user": "你的QQ号@qq.com",
    "password": "十六位授权码",
    "to": "你的QQ号@qq.com"
  }
}
```

#### 什么时候会收到

**只在两种情况推**：① 三个信号里任意一个的成立状态发生变化；② 三项全部成立（抄底时刻）。
状态没变就不打扰你——所以连续几天都「管住手」时收不到消息是正常的，不是坏了。

> 在 GitHub 上跑（方案 C）时，`config.json` **不要**提交到仓库，改用 **Settings → Secrets and variables → Actions** 保存：
> `FEISHU_WEBHOOK`、`FEISHU_SECRET`、`SERVERCHAN_SENDKEY` 三个名字，工作流每次运行会自动拼成 `config.json`。

## 方案 C：全自动 + 手机可看（免费，配置一次后完全不用管）

用 GitHub 的免费定时任务 + 免费网页托管 + 微信提醒。**不用装软件、不用开电脑**。

> **技术部分我已经全部写好并验证过了**：`.github/workflows/daily.yml` 里已经配好「取真实数据 → 算四个信号 → 信号变化推微信 → 发布网页 → 存历史」的完整流程，你一个文件都不用改。
> 只剩下 5 步需要你本人点一下，因为要用到**你的 GitHub 账号**和**你的微信**，我这边没有权限代做。

### 你要做的 5 步（约 10 分钟）

1. **建仓库**：打开 <https://github.com> 注册/登录（免费）→ 右上角 `+` → `New repository` → 名字填 `weipan-board`（随便起）→ 选 **Public** → **不要勾选任何初始化文件**（README、.gitignore、license 都别勾）→ 点 `Create repository`。

2. **上传文件**：在仓库页面点 `uploading an existing file`（或 `Add file` → `Upload files`），把本文件夹里**所有文件和子文件夹一起拖进去**（`index.html`、`assets/`、`data/`、`scripts/`、`docs/`、`.github/`，以及 `.gitignore` 等以点开头的文件）。`data/` 里的 `.trade_days.json`、`.last_state.json` 也要一起上传，GitHub 网页版拖拽会把它们带进去。然后点 `Commit changes`。

### 历史数据是真实的，不是推算的

`history_real.csv` 里 **2148 个交易日（2018-01-02 ~ 2026-11-11）** 的每一天，都是：

1. 拉取**那一天**全市场每只股票的真实市净率与真实总市值；
2. 按**那一天**的总市值排序，剔除北交所 / ST / 退市 / 异常 PB 后选出最小的 400 只；
3. 用这 400 只**当天**的真实 PB 做等权调和平均，得到当天的微盘 PB。

**每天都重新选成分股**，用的是当天真实截面，不是"固定用今天的 400 只成分股去反推历史"，也不是股价比例外推。因此它与原作者「每日重选最小 400 只」的口径一致，是真实历史数据。

| 2024-02-07 | 1.3569（历史最低） | 微盘股流动性危机谷底 |
| 2024-09-18 | 1.4402（次低） | 924 行情前的市场底 |

**近 1800 个交易日 25% 分位 = 2.1089**，由这条真实序列滚动计算，直接用于「微盘做多信号」的纵向打分。原作者 2026-07-24 公布的参考线 2.087 只作为真实样本不足时的兜底，正常情况不会用到。

### 用 akshare 能不能拿到（可以）

**能，而且底层就是同一个数据源。** akshare 的官方接口 `stock_value_em(symbol)` 封装的正是东方财富 `RPT_VALUEANALYSIS_DET` 报表，返回的「市净率」= 真实 `PB_MRQ`、「总市值」= 真实 `TOTAL_MARKET_CAP`。实测可回溯 **2018-01-02 ~ 2026-11-12 共 2149 个交易日**，字段齐全、单次约 0.2 秒。

但有一个关键区别：**akshare 官方接口是「一只股票 × 全部历史」维度，没有「某个交易日 × 全市场截面」的现成接口**。微盘 PB 要求每天都按当日真实市值重选最小 400 只，所以纯靠 `stock_value_em` 拼截面需要遍历约 5400 只股票（每只 1 次请求）；而且实测 `stock_info_a_code_name`、`stock_zh_a_spot_em` 在部分网络环境下会连接失败，不如直接按交易日取稳。

**推荐做法**：`backfill_akshare.py` 用 akshare 取真实交易日历、用 akshare 的请求层访问同一个报表，只把过滤条件换成「按交易日 + 按总市值升序」——**每个交易日 1 次请求**。它与 `backfill_real.py` 等价，两者任选其一，输出都是 `history_real.csv`。

```bash
python backfill_akshare.py --check       # 抽样 8 天校验，不写文件
python backfill_akshare.py               # 增量补齐（跳过已完成日期）
python backfill_akshare.py --force       # 全量重算（约 125 秒）
python backfill_akshare.py --start 20240101 --workers 7
```

实测结果：全量 **2149 天、0 失败、125 秒**；与现有 `history_real.csv` 重叠的 **2148 天逐行完全一致**（PB、平均市值、中位数、有效股票数 4 列零差异），真实 25% 分位 2.1089 vs 2.1085（差异仅来自 akshare 版多含 11-12 一天）。

**几个不能替代的接口**（都已实测）：

| 接口 | 问题 |
|---|---|
| `stock_a_all_pb()`（乐咕全A等权 / 中位数 PB） | 口径是**全 A 等权**，不是「最小 400 只调和平均」；且实测抓取报错 |
| `stock_market_pb_lg()` / `stock_index_pb_lg()` | 板块 / 指数整体 PB，无法重选最小 400 只 |
| `stock_zh_valuation_baidu()` | 单只股票、百度口径，且只有近 1–10 年可选项 |
| `stock_zh_a_spot_em()` | 只有**当前**快照，没有历史截面 |

简单说：akshare 里能拿到真实个股历史估值，但没有现成的「每日全市场截面」接口；用 `backfill_akshare.py` 换一下过滤维度即可，数据本身完全真实、与看板内置序列一致。

### 诚实的局限

- **东财 PB 是 `PB_MRQ`**（按最新报告期净资产），与原作者使用的 Wind / 问财口径可能有极细微差异；11/11 两套独立数据源复算结果 2.0168 vs 2.0169，差异可忽略。
- **扩散指数历史**（400 只站上 MA20 的比例）仍需逐日全市场 K 线，本看板只对**当日**做真实计算；历史扩散指数可从今天起逐日积累。
- 东财报表在交易日收盘后（约 15:00–17:00）更新，建议 15:30 之后运行。

## 档位的历史表现（在条件 2 的星级面板里）

你给的公众号文章《微盘抄底看几颗星？五星亮起后的109次买入，没有一次亏钱》（莱言维语，2026-09-20）对肥常那套系统做了十年回测。**这张表在「今日信号」卡里、点条件 2 当前状态那行 `胜率 / 涨幅` 展开后的面板里**。主表按**星级由低到高**排（0–2 星 → 2.5 星 → 3 星 → 3 星+PB<2 → 3.5 星 → 4 星 → 4.5 星 → 5 星），当前所在档位整行高亮并标「当前」。

**全表只有一个刻度：星。** 做多信号满分 5 星、半星一档，所以有 2.5 星、3.5 星这种档位。上一版页面同时用「分」和「星」两个叫法（分数四舍五入成星级），看的人很容易以为「拆解」和「胜率表」在说两件事；这一版把「分」彻底删掉，历史档位也按这同一个 5 星刻度**重算**——所以表里的天数和胜率和上一版不同。**不是数据变了，是分档口径换了**：上一版是按原文那套「4 个宽基各 1 分、四舍五入成整数星」，现在按本看板这套「1 个时序项 + 8 个对比对象，每项 0.5 星」。

按新口径（**2018-01-02 至 2026-11-11**，2148 个交易日逐日记档）：

展开后的面板顶部就写着这行区间，避免把「2148 个交易日」误当成别的口径。

跨过 3 星线之后，各档的胜率和平均涨幅都明显抬升，这是这张表唯一稳定的结论；2.5 星、3 星这些靠近阈值的档位样本少、窗口高度重叠，单个数字别当真。

下面这个折叠条「触发档位统计」是**原文自己的口径**——4 个宽基各 1 分、整数星级、按**触发次数**统计（5 星 → 4 星 → 3 星 → 3 星+PB<2 → 0 星），用来和文章对照，**和上面主表的数字不能直接比**。触发表三列的意思分别是：

| 列 | 含义 |
|---|---|
| 历史上出现 | 这个档位在样本里一共触发过多少次（原文 2016-09 起 + 本看板 2026-09-20 之后累加） |
| 120 日后平均涨幅 | 触发当天买入、持有 120 个交易日的平均涨跌幅，横条长度就是它 |
| 120 日后上涨 | 这些触发里有多少次 120 日后是涨的，例如 `18 / 18` 就是 18 次全涨 |

主表（星级由低到高那张）**按交易日统计**，不是按触发次数。表头写「样本」，「0–2 星 · 1551 天」就是这一区间里所有交易日加起来的个数（原文口径下同样的 0–2 星是 1628 天，两者不是同一套算法）。

**这张表的表头怎么读**：上面一层 `持有 20 / 60 / 120 个交易日` 是持有期——**当天买入、第 N 个交易日卖出**，不是「最近 N 个交易日」；下面一层每档拆成两列，`胜率` 是这一档所有交易日里 N 日后收盘高于当天的比例，`平均涨幅` 是同一批样本 N 日涨跌幅的均值（红色为涨、绿色为跌，跟 A 股一致）。以前这两组数挤在一个格子里（大的是胜率、小的是涨幅），容易看错，现在分开成两列。`3 星 + PB<2` 是从 3 星的 105 天里再筛出 PB<2 的 57 天，**和上一行重叠**，所以缩进成子行、标「子集」，不参与合计。

- **新触发怎么更新**：2026-09-20 之后每出现一次新触发，「历史上出现」立刻 +1，并在下面用小字标「9 月后 +N 次」和「未满期 N 次 +x%」（这几次到目前的浮动收益）。要等触发满 120 个交易日，才会并入「平均涨幅」和「上涨次数」两列——这是 120 日口径决定的，不是没更新。
- **0 星**那一行（原文口径触发表的最末行）没有 120 日档位，写的是 **871 天**——这是原文口径下 0 星这个状态一共占用了 871 个交易日，**不是触发次数**。因为低星是常态、没有单独的触发档位，只能按天统计，作为「不建仓」的对照：这段时间之后 60 日平均跑输基准 4.2%。表头的 `?` 和脚注都写了这一点。

同一个面板最下面的折叠条是**深跌低点明细**：以自建微盘 400 只等权组合的净值为准，从近一年最高点回落 ≥16% 起算、到回撤收窄回 7% 以内为止算一段深跌，取这段的最低点。表里写日期、回撤幅度、当天 PB 与信号、之后 20/60/120 日涨幅；`★ 原文` 是原文点到的 4 个时刻（2024-02-07、2025-01-06、2025-04-07、2026-07-22），全部被这条规则自动识别。**以后每次出现新的深跌，全景图上会自动多一根紫柱、这张表里也会多一行，低点当天就能看到**，不用等 120 天。它和「0/3 项」是两套口径：一个是跌幅，一个是三个信号，不必一致。

### 原文的核心结论

| 结论 | 数字 |
|---|---|
| 基准（随便挑一天买入） | 20 日 +2.25%、60 日 +6.59% |
| 5 星共 117 天，其后 60 日 | 109 个可统计窗口全部上涨，平均 +14.3% |
| 首次升至 5 星（10 年 19 次） | 60 日 +19.0%、120 日 +32.5%，胜率 100% |
| 星级分布 | 0 星 44.8%、1 星 22.5%（合计 67.3%）；4 星以上仅 14%；5 星 117 天 |
| 0 星（防守价值） | 之后 60 日超额 **−4.24%**，t = −8.6，全表显著性最高 |

**四档实战用法**（原文卡片）：升破 3 星＝预警（40 次 / 120 日 +26.1% / 胜率 73%）；升破 4 星＝确认入场（32 次 / +22.2% / 79%）；首次升至 5 星＝极值扳机（19 次 / +32.5% / 100%）；升破 3 星且 PB<2.0＝双重确认（18 次 / +47.1% / 100%，性价比最高）。

**三个反直觉**：① 最准的信号会先挨打（19 次里 10 日为负 7 次，14 次在 20 日均线下方；但信号是月度级指标，秩相关从 5 日 0.091 升到 120 日 0.399）；② 叠加 PB<2.0 是唯一值得配的保险，**单独叠加扩散<20% 反而变差**；③ 系统一半的价值是「在 0–1 星管住手」。

### 我方独立复核（全部真实数据）

`backtest_real.py` 用东财每日全市场真实截面，逐日重选最小 400 只算 PB 与 8 指数 PB，按文章口径打星；价格不依赖拿不到的万得微盘股指数，而是用**前一日选出的 400 只在次日的真实涨跌幅（CHANGE_RATE）**自建等权净值（t 日选股、t+1 日持有，无前视偏差，且涨跌幅已含除权处理）。2148 个交易日、0 失败。

| 关键量 | 原文 | 我方真实复核 |
|---|---|---|
| 基准 20 / 60 日 | +2.25% / +6.59% | **+2.52% / +7.91%** |
| 0–1 星占比 | 67.3% | **68.2%**（871 + 596 天） |
| Spearman 5 → 120 日 | 0.091 → 0.399 | **0.128 → 0.382** |
| 星级≥3 天数 | 538 天 | **520 天** |
| 叠加 PB<2.0 的 60 / 120 日超额 | +11.1% / +28.6% | **+11.41% / +28.06%** |
| 0 星 60 日超额 | −4.24% | **−3.02%** |
| 各星级 60 日超额（0→5 星） | −4.2 → +7.7% | **−3.02 → +20.36%**（单调递增） |

区间、价格口径都不同，数字不必逐位对齐；**关键是方向、排序和量级高度一致**——这反过来也验证了自建等权组合确实复现了微盘指数的收益特征。主看板顶部结论表把最关键的「四档实战用法」做了「原文 / 我方」并列，并附 4 个核心结论的对照数字。

### 结论表的诚实边界

- **四档胜率显示 100% 属于高估**：120 日窗口未满的近期信号被统计自动排除，加上信号窗口大量重叠。真正稳健的是「高星段平均收益与超额随星级递增」这一排序关系，不是某个胜率数字。结论表下方已标注。
- **历史扩散指数没能回溯**：需要逐日全市场 MA20，免费渠道做不到，所以「叠加扩散<20%」「三项条件全部成立」两项的组合叠加结论**引用原文**，我方只复核了「星级≥3」与「叠加 PB<2.0」两项。
- **价格口径不同**：原文用万得微盘股指数（理论指数），我方用自建最小 400 只等权组合（含每日轮动与再平衡），绝对收益不可直接当指数看；但基准 60 日 +7.91% vs 原文 +6.59% 说明两者收益特征接近。
- **区间短两年**：东财报表最早到 2018-01-02，缺少 2016.9–2017 年微盘 PB 高位段，星级分布与原文必然不同（我方 5 星 32 天 vs 原文 117 天）。
- **宽基成分股**按当前名单回溯匹配，未还原历史调样；近 1800 日分位在早期样本不足时用扩展窗口。
- 原文自身提示：理论指数只能用小微盘基金参与（有跟踪误差）、窗口重叠使 t 值偏乐观、2026 年 4 次信号周期未走完；**整套体系建立在微盘股定价规律之上，若该规律被证伪则信号失效**。

## 常见问题

- **打开还是旧版 / 看不到「版本 v26.8」标签？** 这是浏览器缓存，不是文件旧。处理顺序：
  1. **强制刷新**：电脑上按 `Ctrl + F5`（Mac 是 `Cmd + Shift + R`）；手机浏览器在设置里清一次「缓存」，或直接用无痕/隐私窗口打开。
  2. **确认打开的是哪份文件**：如果你之前把旧包解压到 `桌面\weipan-board`，新包又解压到 `桌面\weipan-board (1)`，双击的很可能还是旧目录。建议先把旧文件夹整个删掉，再解压新包。
  3. **看 GitHub Pages**：网页版上传后要等 1–3 分钟构建；地址后面加个 `?v=6`（如 `xxx.github.io/weipan-board/?v=6`）可绕过 CDN 缓存。
  4. **网页版有两条曲线是空的？** 一定是 `bt_data.js` 或 `extra_hist.js` 没上传成功（手机上打开本地包能看到，说明文件本身没问题）。到「数据与更新」卡里看那行自检：两个 ✓ 才算齐，出现 ✗ 就把对应文件重新上传一次。
- **数据没变化？** 非交易日或节假日的收盘数据不会变，正常。请在交易日 15:30 之后运行。
- **桌面通知没弹？** 点一下「🔔 测试提醒」授权；若显示「被浏览器拒绝」，在浏览器地址栏左侧的站点设置里把通知改回「允许」。页面内的橙色横幅和提示音不受浏览器权限影响。
- **数值和雪球作者发的略有差异？** 作者的表格用的是同花顺问财口径，本看板用新浪行情复算，成分股过滤细节不同会有 1 只股票级别的微差，不影响信号判断。
- **提示"行情数据量异常"？** 网络波动，稍等几分钟重跑即可。
- **脚本能算未来数据吗？** 不能，只反映最新已收盘交易日。
